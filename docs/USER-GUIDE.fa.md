## ۱. معرفی

💡 کنار عنوان بیشتر بخش‌های صفحه‌های افزونه یک آیکون **«؟**» دیده می‌شود؛ با کلیک روی آن، توضیح کوتاهی از همان بخش باز می‌شود — در همین راهنما هم به همهٔ آن بخش‌ها پرداخته‌ایم.

**AI Post Creator** وردپرس شما را به یک «ایجنت محتوا» تبدیل می‌کند. شما فقط یک بار
اطلاعات سایت و اتصال هوش مصنوعی را تنظیم می‌کنید؛ بعد ایجنت:

1. دسته‌بندی مناسب را از بین دسته‌های موجود سایت انتخاب می‌کند و موضوع را از
   «پرامپت سایت» می‌سازد (یا از موضوع پیشنهادی شما استفاده می‌کند)
2. طرح مقاله را می‌نویسد و بخش‌به‌بخش محتوا تولید می‌کند
3. یک **پاس کپی‌رایتینگ و سئو** روی کل متن اجرا می‌کند
4. متادیتای سئو (Rank Math / Yoast)، برچسب‌ها، نامک و چکیده می‌سازد
5. **تصویر شاخص** تولید و پیوست می‌کند
6. نتیجه را به‌صورت **پیش‌نویس** ذخیره می‌کند (یا طبق انتخاب شما منتشر می‌کند)

همهٔ مراحل به‌صورت زنده در «کنسول ایجنت» دیده می‌شوند و در صورت خطا، هر مرحله تا
۳ بار خودکار تلاش مجدد می‌شود.

**جریان‌های اصلی:**

- 🆕 **نوشتهٔ جدید** — از صفر تا صد
- ♻️ **بازنویسی نوشتهٔ موجود** — تازه‌سازی کامل یک پست قدیمی

## ۲. نصب و راه‌اندازی

**پیش‌نیازها:** وردپرس ۵.۷ به بالا، PHP 7.4 به بالا

1. پوشهٔ `wp-ai-post-creator` را در `wp-content/plugins/` کپی کنید (یا فایل zip را
   از «افزونه‌ها → افزودن» نصب کنید)
2. افزونه را فعال کنید
3. منوی جدید **AI Post Creator** در پیشخوان ظاهر می‌شود

کلیدهای API فقط در دیتابیس سایت خودتان ذخیره می‌شوند و به هیچ سرویس دیگری جز
تأمین‌کنندهٔ انتخابی شما ارسال نمی‌شوند.

## ۳. اتصال هوش مصنوعی (اولین قدم)

مسیر: **AI Post Creator → Connections**

هر سرویس سازگار با OpenAI کار می‌کند: OpenAI، OpenRouter، Groq، DeepSeek، Together،
Ollama، LM Studio و…

| فیلد | توضیح |
|---|---|
| نام | فقط برچسب نمایشی (مثلاً «OpenAI متن») |
| Base URL | مثل `https://api.openai.com/v1` — نقطهٔ پایانی سازگار با OpenAI |
| کلید API | فقط نوشتنی است؛ خالی بگذارید یعنی «همان قبلی بماند» |
| مدل گفتگو | مثل `gpt-4o-mini` — با دکمهٔ «بارگذاری مدل‌ها» از خود سرویس بگیرید |
| مدل تصویر | مثل `dall-e-3` یا `gpt-image-1` |
| کاربرد *(جدید در ۱.۸)* | این اتصال برای چه استفاده شود: **گفتگو و تصویر** (پیش‌فرض)، **فقط گفتگو** یا **فقط تصویر** |
| مسیر تولید تصویر *(جدید در ۱.۹)* | **خودکار** (اول اندپوینت تصویر، بعد گفتگو)، **اندپوینت تصویر** (سبک OpenAI) یا **گفتگو** (گیت‌وی‌های سبک Gemini/OpenRouter — در «مدل تصویر» یک مدل تصویرساز مثل `gemini-2.5-flash-image` بگذارید) |
| دریافت تصویر *(جدید در ۱.۸.۱)* | **خودکار** (Base64 یا لینک) یا **اجباری Base64** — بایت‌های تصویر داخل خودِ پاسخ API می‌آید و همان‌جا محلی تبدیل می‌شود؛ اگر فقط لینک بیاید، اجرا سراغ اتصال تصویر بعدی می‌رود |
| اولویت *(جدید در ۱.۸)* | ۱ تا ۹۹۹، عدد کوچک‌تر = زودتر امتحان می‌شود — بعد از ۳ خطای پیاپی، اتصال هم‌کاربردِ بعدی جایگزین می‌شود |
| فعال *(جدید در ۱.۹.۳)* | تیک را بردارید (یا در جدول روی «غیرفعال کردن» بزنید) تا اتصال ذخیره بماند ولی در هیچ اجرایی شرکت نکند — استخرها، زنجیره‌های جایگزین و انتخاب پیش‌فرض همه از آن رد می‌شوند |
| دما / سقف توکن / مهلت | تنظیمات دقیق مدل (پیش‌فرض‌ها مناسب‌اند) |

- **اتصال پیش‌فرض:** اولین اتصال یا هر اتصالی که «پیش‌فرض» بگذارید، برای همهٔ
  مراحل استفاده می‌شود.
- قبل از ذخیره، با «تست اتصال» صحت نشانی و کلید را بررسی کنید.
- **چند اتصال تعریف کنید** تا در بخش ۸ بتوانید برای هر مرحله زنجیرهٔ جایگزین بسازید.

**سرور جدا برای تصویر (جدید در ۱.۸):** یک اتصال با کاربرد «فقط تصویر» بسازید
(مثلاً گیت‌وی یا سروری که مدل تصویرتان را دارد) و اتصال متنی‌تان را «فقط گفتگو»
کنید. از این به بعد گام‌های متنی از استخر گفتگو و گام تصویر شاخص از استخر تصویر
استفاده می‌کنند — هر کدام به‌ترتیب اولویت و با جایگزینی خودکار بعد از ۳ خطا.
زنجیره‌های دستیِ هر گام (بخش ۸) همیشه بر این استخرهای خودکار مقدم‌اند.

## ۴. تنظیمات سایت

مسیر: **AI Post Creator → Settings**

| تنظیم | توضیح |
|---|---|
| **پرامپت سایت** ⭐ | مهم‌ترین تنظیم: سایت شما چیست، هدف و مخاطبش کیست، چه لحنی دارد. ایجنت از همین موضوع و دسته‌بندی و عنوان می‌سازد |
| **سایت‌های مبدأ پژوهش** | اختیاری — هر خط یک نشانی (حداکثر ۸). ایجنت هنگام برنامه‌ریزی فید RSS هر سایت را می‌خواند و موضوع و واقعیت‌ها را با آخرین مطالبشان هم‌راستا می‌کند |
| زبان محتوا | ۱۲+ زبان از جمله فارسی (پیش‌فرض از زبان سایت) |
| لحن و طول پیش‌فرض | لحن (رسمی، صمیمی، …) و طول (کوتاه ~۶۰۰ / متوسط ~۱۲۰۰ / بلند ~۲۲۰۰ کلمه) |
| تصویر / فهرست مطالب / پرسش‌های متداول | پیش‌فرض‌های هر اجرا — اندازهٔ تصویر علاوه بر پیش‌تنظیم‌ها گزینهٔ «سفارشی…» با عرض×ارتفاع دلخواه دارد *(جدید در ۱.۱۲.۱)* |
| پرامت پیش‌فرض تصویر *(جدید در ۱.۱۰)* | به انتهای هر پرامت تصویر تولیدشده افزوده می‌شود — برای یکدست شدن سبک همهٔ تصاویر شاخص (پالت رنگ، سبک هنری) |
| لینک منبع *(جدید در ۱.۱۲)* | مقاله‌ها به سایت‌های منبع پژوهش لینک بدهند یا نه — خاموش = منابع فقط برای واقعیت‌ها، لینک‌ها حذف می‌شوند |

> 🔗 از نسخهٔ ۱.۱۲ هر لینک داخلی در هر مقاله حداکثر یک بار استفاده می‌شود —
> لینک‌های داخلی تکراری خودکار به متن ساده تبدیل می‌شوند.

> 🔍 **اشکال‌زدایی مراحل یا تصویرهای ناموفق (جدید در ۱.۱۱):** در Settings →
> Advanced گزینهٔ «لاگ کامل API» را روشن کنید تا همهٔ درخواست‌ها و پاسخ‌های
> هوش مصنوعی (پرامت‌ها، پاسخ مدل، متن کامل خطاها، کد و زمان، با کار/مرحله/
> اتصال/شمارهٔ تلاش) در یک فایل محافظت‌شده ثبت شود؛ فایل را دانلود و بررسی
> کنید — کلیدها حذف و base64 فشرده می‌شود. بعد از اشکال‌زدایی خاموشش کنید.

> ✍️ از نسخهٔ ۱.۱۰ نیم‌فاصله‌ها خودکار حفظ می‌شوند: الگوهای رایج (می/نمی + فعل،
> پسوندهای ها/تر/ترین) در خروجی هوش مصنوعی اصلاح و نویسهٔ نیم‌فاصله در متن نوشته
> به‌صورت `&zwnj;` ذخیره می‌شود تا هیچ ویرایشگری نتواند حذفش کند.
> 🖼 در فهرست نوشته‌ها (نوشته‌ها → همهٔ نوشته‌ها) هم گزینهٔ **«ساخت مجدد تصویر
> شاخص»** اضافه شده — با یک کلیک تصویر شاخص تازه‌ای برای همان نوشته ساخته و
> تنظیم می‌شود.

> 💡 نمونهٔ پرامپت سایت: «یک وبلاگ فارسی درباره باغبانی خانگی برای مبتدیان؛
> لحن گرم و تشویقی، تمرکز بر راه‌حل‌های کم‌هزینه برای آپارتمان.»

## ۵. ساخت نوشتهٔ جدید

مسیر: **AI Post Creator → New AI Post**

1. **موضوع (اختیاری):** خالی بگذارید تا ایجنت خودش از پرامپت سایت موضوع بسازد؛ یا
   ایدهٔ خودتان را بنویسید. ایجنت نوشته‌های موجود سایت را می‌بیند و موضوع تکراری
   انتخاب نمی‌کند.
2. **گزینه‌ها:** لحن، طول، زبان، تصویر شاخص، بلوک FAQ (+ اسکیمای گوگل)، فهرست مطالب.
3. **پس از ساخت (جدید در ۱.۵):** یکی از سه حالت را انتخاب کنید:
   - 📝 **پیش‌نویس بماند** (پیش‌فرض — همیشه امن)
   - 🚀 **انتشار بلافاصله** بعد از اتمام
   - ⏱ **انتشار بعداً** — بعد از ۱۵ تا ۱۰۰۸۰ دقیقه (تا یک هفته)
4. دکمهٔ **«تولید نوشته»** را بزنید و کنسول را تماشا کنید.

**کنسول ایجنت:** نوار پیشرفت، وضعیت تک‌تک مراحل، لاگ زنده، مصرف توکن. اگر مرحله‌ای
بعد از همهٔ تلاش‌ها خطا داد، دکمهٔ **«تلاش دوباره»** فقط همان مرحله را اجرا می‌کند؛
**«لغو»** هر لحظه کار را متوقف می‌کند.

**اجرای پس‌زمینه (جدید در ۱.۶):** کار روی خود سرور اجرا می‌شود — می‌توانید تب مرورگر را
ببندید، کار ادامه پیدا می‌کند. کنسول فقط نتیجه را زنده نشان می‌دهد و اگر مدتی پیشرفتی
دیده نشود، هشدار می‌دهد (مثلاً وقتی WP-Cron سایت کار نمی‌کند).

**لینک‌سازی داخلی:** ایجنت هنگام برنامه‌ریزی، نوشته‌های مرتبط سایت شما را می‌بیند و
تا ۴ لینک داخلی را به‌طور طبیعی داخل متن می‌نوید — بدون دخالت شما.

## ۵٫۵. صندوق بازبینی پیش‌نویس‌ها (جدید در ۱.۶)

مسیر: **AI Post Creator → Review drafts**

همهٔ پیش‌نویس‌هایی که هوش مصنوعی ساخده — دستی یا زمان‌بندی‌شده، جدید یا بازنویسی‌شده —
در یک صفحه جمع می‌شوند: عنوان، وضعیت، تعداد کلمات، مبدأ (دستی / زمان‌بندی‌شده /
بازنویسی) و زمان آخرین تغییر. برای هر پیش‌نویس:

- ✎ **ویرایش نوشته** — باز شدن ویرایشگر وردپرس
- 👁 **پیش‌نمایش** — دیدن خروجی در مرورگر
- 🚀 **انتشار** — انتشار یک‌کلیکی با تأیید (فقط کاربران دارای مجوز انتشار)
- ♻️ **بازنویسی** — ارسال مستقیم همان نوشته به صفحهٔ بازنویسی

چیزی تا خودتان منتشر نکنید، منتشر نمی‌شود — سیاست همیشگی افزونه.

## ۶. بازنویسی نوشتهٔ قدیمی (جدید در ۱.۵)

مسیر: **AI Post Creator → Rewrite post**

1. پست موردنظر را از فهرست (۱۰۰ پست آخر بر اساس آخرین ویرایش) انتخاب کنید
2. گزینه‌ها را تنظیم کنید (تصویر شاخص **جدید**، FAQ جدید، لحن و زبان تازه)
3. **«بازنویسی نوشته»** را بزنید

ایجنت: نوشته را **تحلیل** می‌کند → کل متن را با نگاه کپی‌رایتینگ/سئو **بازنویسی**
می‌کند (واقعیت‌ها و همهٔ لینک‌ها حفظ می‌شوند، لینک داخلی مرتبط اضافه می‌شود) →
متادیتای سئو را تازه می‌کند → در صورت فعال‌بودن، تصویر شاخص جدید می‌سازد.

**مهم:** پست **درجا به‌روزرسانی** می‌شود — وضعیت (پیش‌نویس/منتشر)، نویسنده، نشانی
(namak) و دسته‌بندی دست‌نخورده می‌مانند؛ برچسب‌های جدید اضافه می‌شوند. پس قبل از
بازنویسی پست‌های مهم، از محتوا نسخهٔ پشتیبان داشته باشید.

## ۷. زمان‌بندی خودکار + انتشار خودکار

مسیر: **AI Post Creator → Schedule**

هر زمان‌بندی شامل: ساعت (به وقت سایت)، روزهای هفته، موضوع (ثابت یا خالی = خودکار)،
گزینه‌های اجرا، و — جدید در ۱.۵ — **تنظیم انتشار** (پیش‌نویس / فوری / با تأخیر).

- ایجنت هر ۱۵ دقیقه بیدار می‌شود؛ زمان‌بندی‌های سرآمده را همان روز جبران می‌کند و
  هیچ‌وقت دوبار اجرا نمی‌کند.
- اجرای interrupted خودکار از سر گرفته می‌شود و اجرای خطادار تا ۳ بار تکرار می‌شود.
- **سقف روزانه:** حداکثر N پست خودکار در روز (۰ = بی‌نهایت). شمارش امروز روی همان
  صفحه نمایش داده می‌شود.
- دکمهٔ **«همین حالا اجرا کن»** هر زمان‌بندی را فوری در کنسول زنده اجرا می‌کند.

> ⏱ **انتشار با تأخیر** چطور کار می‌کند؟ پست مثل همیشه اول پیش‌نویس ساخته می‌شود،
> بعد یک رویداد زمان‌بندی‌شدهٔ امن آن را در زمان مقرر منتشر می‌کند (فقط اگر هنوز
> پیش‌نویس باشد) و به همهٔ گیرنده‌های بله پیام 🎉 می‌دهد.

### 📋 صف موضوع‌ها (جدید در ۱.۷)

روی همان صفحهٔ زمان‌بندی، کارت **«صف موضوع‌ها»** را ببینید:

- هر زمان‌بندی که گزینهٔ **«موضوع را از صف بردار»** را دارد، هنگام اجرا قدیمی‌ترین
  موضوعِ در انتظار را برمی‌دارد و صف جلو می‌رود؛ اگر صف خالی باشد به موضوع ثابت
  خودِ زمان‌بندی (یا توضیح سایت) برمی‌گردد.
- **افزودن دستی:** چند موضوع را خط‌به‌خط در کادر بنویسید و «افزودن به صف» را بزنید.
- **پیشنهاد هوشمند:** دکمهٔ **«پیشنهاد موضوع از منابع من»** تیترهای تازهٔ همان
  منابعی را که در تنظیمات ثبت کرده‌اید می‌خواند، نام منابع انتهای تیترها را
  پاک می‌کند و موارد تکراری (با صف و با نوشته‌های قبلی سایت) را حذف می‌کند؛
  شما تیک می‌زنید و به صف اضافه می‌شود.
- موضوع‌های استفاده‌شده به خاطر سپرده می‌شوند تا هیچ‌وقت دوباره پیشنهاد نشوند؛
  «خالی کردن صف» فقط موارد در انتظار را برمی‌دارد.

> از داخل بله هم می‌توانید صف را ببینید: فرمان **«صف»** (بخش ۹).

## ۸. اتصال‌ها و مراحل: چند AI با جایگزینی خودکار

مسیر: **AI Post Creator → Prompts & Steps**

- هر مرحله (موضوع‌یابی، مقدمه، هر بخش، کپی‌رایتینگ، سئو، تصویر و…) می‌تواند
  **زنجیرهٔ اتصال خودش** را داشته باشد: با Ctrl/Cmd چند اتصال را به‌ترتیب انتخاب کنید.
- **سمنتیک جایگزینی:** هر اتصال در زنجیره تا ۳ بار تلاش می‌کند؛ اگر مدام خطا خورد،
  ایجنت خودکار به اتصال بعدی می‌رود (در لاگ کنسول «تغییر به …» را می‌بینید).
- اگر **کل زنجیرهٔ تصویر** شکست بخورد، پست بدون تصویر ادامه می‌کند — چیزی خراب نمی‌شود.
- خالی بگذارید یعنی «اتصال پیش‌فرض».

**کاربرد واقعی:** متن با OpenAI، تصویر با سرویس دوم، و برای مراحل حساس یک سرویس
پشتیبان مثل Groq — اگر اولی قطع شد، سایت شما متوقف نمی‌شود.

### ویرایش پرامپت‌ها
قالب پرامپت هر ۱۳ مرحله قابل ویرایش است. جای‌نگهدارها داخل `{{…}}` هستند و جدول
توضیحاتشان زیر هر پرامپت نمایش داده می‌شود. اگر پرامپتی را دست نزنید، در حالت
«پیش‌فرض» می‌ماند و با به‌روزرسانی افزونه بهبود می‌خورد؛ تیک «بازنشانی» آن را به
پیش‌فرض برمی‌گرداند.

## ۹. اطلاع‌رسانی بله

مسیر: **AI Post Creator → Schedule → بخش «اطلاع‌رسانی بله»**

1. در بله با [@Bot_Father](https://web.bale.ai/) یک ربات بسازید و توکنش را کپی کنید
2. توکن را در فیلد «توکن ربات» بگذارید (تنها نوشتنی — برای نگه‌داشتن فعلی خالی بگذارید)
3. **گیرنده‌ها:** هر خط یک شناسه — شناسهٔ عددی شخص یا @نام‌کانال
4. یک پیام به رباتتان بفرستید و دکمهٔ **«شناسایی خودکار شناسه گفتگو»** را بزنید
5. «ارسال پیام آزمایشی» همهٔ گیرنده‌ها را یکجا تست می‌کند

بعد از هر پست (دستی یا زمان‌بندی‌شده) به همهٔ گیرنده‌ها یک پیام آمادهٔ کانال
می‌رود: `🔻عنوان`، `🌱🌱خلاصه🌱🌱`، سطر «ادامه مطلب در لینک زیر👇👇👇» و لینک —
و **تصویر شاخص بالای پیام** فرستاده می‌شود. اگر نوشته تصویر شاخص نداشت،
**تصویر پیش‌فرض اعلان** (جدید در ۱.۹.۲ — نشانی‌اش را در همین بخش بگذارید)
جایگزین می‌شود؛ خالی بگذارید تا در آن حالت فقط متن برود. نتیجهٔ تحویل به هر
گیرنده در لاگ کار ثبت می‌شود.

**گزارش دوره‌ای:** روزانه یا هفتگی — خلاصهٔ فعالیت (کارها، موفق/ناموفق، پیش‌نویس‌ها،
توکن‌ها، مصرف به تفکیک اتصال) در ساعت/روز دلخواه برای همه.

### 💬 فرمان از داخل بله (دوسویه — جدید در ۱.۷)

در همان بخش بله، گزینهٔ **«پذیرش فرمان از گفتگوهای بله»** را فعال کنید. ربات
تقریباً هر ۵ دقیقه پیام‌های تازه را بررسی می‌کند و فقط به شناسه‌های گفتگوی
ثبت‌شده در همین صفحه پاسخ می‌دهد؛ از سایر گفتگوها ساکت است.

| فرمان | کار |
|---|---|
| `نوشتن: موضوع` | شروع ساخت پیش‌نویس دربارهٔ همان موضوع (در پس‌زمینه) |
| `وضعیت` | اجراهای امروز، پیش‌نویس‌های در انتظار و صف موضوع‌ها |
| `آخرین` | جدیدترین پیش‌نویس + لینک آن |
| `انتشار` یا `انتشار ۲` | انتشار جدیدترین (یا دومین) پیش‌نویس — عدد فارسی هم پذیرفته است |
| `صف` | موضوع‌های در انتظار در صف |
| `راهنما` | فهرست کامل فرمان‌ها |

- تا **۲۰ نوشته در روز** را می‌توان از داخل بله شروع کرد (گارد هزینه).
- آماده‌شدن پیش‌نویس، مثل همیشه با پیام تصویر + خلاصه + لینک اعلام می‌شود؛
  «انتشار» هم پیام 🎉 انتشار دارد.
- به‌جای «نوشتن:» می‌توانید `/new` و به‌جای بقیه، معادل انگلیسی (status، latest،
  publish، queue، help) را هم بفرستید.

### 🔘 دکمه‌های انتشار / زمان‌بندی (جدید در ۱.۱۳)

وقتی دستورهای دوطرفه فعال باشند، زیر هر اعلان پیش‌نویس دو دکمه می‌آید:

- **🚀 انتشار همین حالا** — پست بلافاصله و با تاریخِ همین لحظه منتشر می‌شود.
- **⏰ زمان‌بندی** — ربات تاریخ را می‌پرسد؛ در یک پیام جواب بدهید:
  `1404/07/20 18:30` (شمسی)، `2026-10-12 18:30` (میلادی)،
  «فردا 18:30» یا «امروز 22:00» — عدد فارسی هم پذیرفته است و اگر ساعت
  ننویسید ۰۹:۰۰ در نظر گرفته می‌شود. پست مثل زمان‌بندی عادی وردپرس
  `scheduled` می‌شود و موقع انتشار، پیام 🎉 هم می‌آید.
  برای انصراف «لغو» بفرستید (درخواست بعد از ۳۰ دقیقه هم منقضی می‌شود).

### 📱 منوی تعاملی (جدید در ۱.۱۴)

«منو» (یا `/menu`) بفرستید — یا اصلاً همان دکمه‌هایی را بزنید که حالا
همراه `/start` و «راهنما» می‌آید:

| دکمه | کارش |
|---|---|
| ✍️ موضوع جدید | ربات موضوع را می‌پرسد؛ پیام بعدی شما نوشتن را شروع می‌کند |
| 📋 صف موضوعات | موضوعات در انتظار — روی هرکدام بزنید تا همان لحظه نوشته شود |
| 📑 پیش‌نویس‌ها | ۵ پیش‌نویس آخر — با کارت اقدام (انتشار همین حالا / زمان‌بندی) |
| 📊 وضعیت | اجراها، پیش‌نویس‌ها و صفِ امروز |
| ❓ راهنما | فهرست دستورها |

هر پیامی که ربات نفهمد، راهنمایی + همین منو را برمی‌گرداند تا هیچ‌وقت
گیر نکنید.

## ۱۰. به‌روزرسانی مستقیم از گیت (۱.۵.۱ + ۱.۵.۲)

مسیر: **AI Post Creator → Update from Git (به‌روزرسانی از گیت)**

- صفحه، نسخهٔ نصب‌شده و نسخهٔ موجود در گیت‌هاب را کنار هم نشان می‌دهد.
- **«همین حالا بررسی کن»** نسخهٔ شاخهٔ انتخابی را از گیت‌هاب می‌خواند.
- **«به‌روزرسانی از گیت»** کل افزونه را درجا به‌روزرسانی می‌کند:
  1. تصویر لحظه‌ای مخزن (zip) دانلود می‌شود
  2. سرآیند افزونه راستی‌آزمایی (بستهٔ خراب رد می‌شود)
  3. از فایل‌های فعلی در `wp-content/aipc-backups` پشتیبان گرفته می‌شود
  4. فایل‌های جدید به‌صورت اتمی جایگزین می‌شوند؛ در صورت هر خطا، نسخهٔ قبلی **خودکار بازگردانده** می‌شود
- تنظیمات، اتصال‌ها، زمان‌بندی‌ها و نوشته‌ها در دیتابیس‌اند و دست نمی‌خورند.
- **اتصال گیت (۱.۵.۲):** در بخش «تنظیمات به‌روزرسانی» **مخزن گیت‌هاب** (`owner/name`)، **شاخه** (پیش‌فرض `main` یا شاخهٔ توسعه) و **توکن دسترسی شخصی (PAT)** را ذخیره کنید:
  - توکن فقط برای مخازن خصوصی و سقف درخواست بالاتر لازم است؛ برای مخزن عمومی خالی بگذارید.
  - توکن **write-only** است: بعد از ذخیره هرگز نمایش داده نمی‌شود و فیلد خالی یعنی «همان قبلی بماند».
  - توکن در یک option جداگانهٔ غیر-autoload و فقط روی سایت خودتان ذخیره می‌شود و تنها از طریق HTTPS به github.com می‌رود.
- **🔌 «تست اتصال»** مخزن + شاخه + توکن را یکجا در برابر گیت‌هاب می‌سنجد و **آخرین نسخه** را گزارش می‌کند (اگر فیلد توکن را خالی گذاشته باشید، توکن ذخیره‌شده تست می‌شود).
- **«همین حالا بررسی کن»** نسخهٔ شاخهٔ ذخیره‌شده را دوباره می‌خواند.
- برای جلوگیری از تنزل نسخه، به‌روزرسانیِ شاخهٔ قدیمی‌تر مسدود است — مگر اینکه «نصب مجدد به هر حال» را علامت بزنید.
- فایل‌هایی که در نسخهٔ جدید حذف شده‌اند هم پاک می‌شوند (به‌روزرسانی کامل، نه روی‌هم‌نویسی).

> ⚠️ نکته: اگر افزونه را با `git clone` نصب کرده‌اید، پوشهٔ `.git` با به‌روزرسانی از دست می‌رود.

## ۱۱. گزارش‌ها

مسیر: **AI Post Creator → Logs**

- **خلاصهٔ کلی:** تعداد کارها، موفق/ناموفق، توکن مصرفی
- **مصرف به تفکیک هر اتصال**
- **فهرست کارها** با صفحه‌بندی + صفحهٔ جزئیات هر کار: زمان‌بندی مراحل، تمام فراخوانی‌های
  API (اتصال، مدل، توکن، مدت، خطا) و بازپخش کامل کنسول
- حذف تک‌کارها یا پاک‌کردن کل لاگ‌ها

## ۱۲. رفع اشکال

| مشکل | راه‌حل |
|---|---|
| «هیچ اتصالی تنظیم نشده» | Connections → یک اتصال بسازید و «پیش‌فرض» بگذارید |
| خطای 401 / Unauthorized | کلید API یا Base URL اشتباه است؛ Base باید تا `/v1` باشد |
| خطای timeout در مراحل | مهلت درخواست اتصال را بالا ببرید؛ مدل سبک‌تر انتخاب کنید |
| تصویر ساخته نمی‌شود | مدل تصویر اتصال را چک کنید؛ اگر کل زنجیره خطا خورد، پست بدون تصویر کامل می‌شود |
| زمان‌بندی اجرا نمی‌شود | در «تنظیمات → نوشته‌ها» صفحه، بررسی کنید wp-cron فعال باشد؛ برای سایت‌های کم‌بازدید یک cron واقعی (دقیقه‌ای) تنظیم کنید |
| پست با تأخیر منتشر نشد | همان شرط wp-cron؛ رویداد فقط با بیدارشدن کران اجرا می‌شود |
| خروجی انگلیسی شد | «زبان محتوا» را فارسی بگذارید (تنظیمات یا گزینه‌های هر اجرا) |
| موضوع تکراری/شبیه پست قبلی | پرامپت سایت را دقیق‌تر کنید؛ لیست نوشته‌های موجود خودکار به ایجنت نشان داده می‌شود |

## ۱۳. سؤالات متداول

**آیا کلید API من جایی ذخیره می‌شود؟**
فقط در دیتابیس سایت خودتان؛ هرگز در مرورگر، REST یا لاگ‌ها ظاهر نمی‌شود.

**اگر وسط کار تب را ببندم چی؟**
هیچ اتفاقی نمی‌افتد — از نسخهٔ ۱.۶ کار به‌طور کامل روی خود سرور اجرا می‌شود و
کنسول فقط تماشاگر است. هر وقت برگردید، ادامهٔ پیشرفت (یا نتیجهٔ نهایی) را
می‌بینید؛ اجرای ناتمام کران هم خودکار از سر گرفته می‌شود.

**آیا محتوا کپی می‌شود؟**
پاس کپی‌رایتینگ روی اصالت متن تمرکز دارد و سایت‌های مبدأ فقط برای الهام/زمین‌گیری
هستند — دستور صریح سیستم: «هرگز جمله‌هایشان را کپی نکن».

**حذف افزونه چه چیزی را پاک می‌کند؟**
فقط اگر در تنظیمات «حذف کامل داده‌ها هنگام حذف افزونه» را فعال کرده باشید، همهٔ
داده‌ها (تنظیمات، کارها، متاها) پاک می‌شوند؛ در غیر این صورت همه‌چیز می‌ماند.

**برای چندسایته (multisite) مناسب است؟**
تست نشده؛ در حال حاضر network-activate توصیه نمی‌شود.
